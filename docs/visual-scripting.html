Scripting

Visual scripting

Snap blocks together to make a script, without typing code. Each visual script is turned into an ordinary C# script, so it runs just as fast and you can read the code it makes.

The VC view

Press VC in the toolbar. The 3D view is replaced by three areas:

  • The palette on the left, with the blocks grouped by category: Events, Motion, Control, Sensing, Variables and Operators.
  • The canvas in the middle, where you build scripts.
  • The block inspector on the right. Click a block to edit its values, see what's plugged into it, or press Duplicate block or Delete block.

The header has New, Save and Check, a name box for the script, a button for each visual script in the project to open it, and 3D view to go back.

Building a script

  • Drag a block from the palette onto the canvas.
  • Drop a block just under another to stack them; they run top to bottom.
  • Drop blocks into the mouth of a C-shaped block (forever, repeat, if) to run them inside it.
  • Drop a round reporter block (a value, like x position or a + b) into a value box of another block.
  • Type numbers and pick keys right in the blocks, or in the block inspector.
  • Drag a block back onto the palette to delete it, with everything below it.
  • Cmd/Ctrl+D copies the selected block and the blocks below it.

Every script starts with an event (hat) block. A visual script can hold several, and they all run side by side.

Saving and attaching

Save writes Scripts/<Name>.visualcode and, next to it, the C# script it turns into, Scripts/<Name>.cs. Attach it to an object like any script: Add Component > Script, then pick its name. Check reports problems without saving. Visual scripts are also converted again each time you press Play.

Edit the blocks, not the .cs

The generated .cs is rewritten on every save and every Play, so changes made to it are lost. The code view shows it read-only. To turn a visual script into hand-written C#, copy the code into a new script with a different name.

Control

BlockDoes
wait () secondsPauses this script

wait until <condition>Pauses until the condition is true

forever and repeat until wait one frame between rounds, so they never freeze the game. repeat () times does not: all its rounds happen in the same frame unless you put a wait inside. To animate something over several frames with repeat, add wait one frame as its last block.

Variables

Type a name under Variables in the palette and press Add. Then use set [var] to (), change [var] by (), and the variable's own reporter block. Variables belong to the script on one object, start at their set value each time play starts, and are not shown in the Inspector.

Operators

+, −, ×, /, mod, >, <, =, and, or, not, and pick random () to (). Division by zero gives 0 rather than an error, and = treats numbers within 0.00001 of each other as equal, so small rounding differences don't matter.

What the blocks turn into

Each event block becomes a coroutine started in Start, and Update keeps them all running. For example, this visual script from the sample project:

when scene starts
    go to x: 0 y: 0 z: 0
    forever
        turn Y by 2 degrees

when W pressed
    move (speed) units forward

becomes:

public class Spinner : Behaviour
{
    private float _v_speed = 1f;

    public override void Start()
    {
        Spawn(Script0());
        Spawn(Script1());
    }

    public override void Update()
    {
        TickRoutines();
    }

    private IEnumerable<Wait> Script0()
    {
        Position = new Vector3(0f, 0f, 0f);
        while (true)
        {
            Turn(new Vector3(0f, 1f, 0f), 2f);
            yield return null;
        }
    }

    private IEnumerable<Wait> Script1()
    {
        while (true)
        {
            if (Input.GetKeyDown("W"))
            {
                MoveForward(_v_speed);
            }
            yield return null;
        }
    }
}

When you outgrow blocks, this is a good starting point for a hand-written script.
