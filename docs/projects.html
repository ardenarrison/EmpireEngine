Projects and Empire Engine Hub

A project is a folder. Empire Engine Hub keeps a list of your projects, makes new ones, and opens each in the editor version it was made with.

What's in a project

My Game/
  project.empire          name, editor version and start scene (written by the Hub)
  Scenes/
    Main.empirescene      a scene: objects, components and scene settings, as JSON
  Models/                 .glb, .gltf, .fbx and .obj files
  Scripts/                .cs scripts and .visualcode visual scripts
  Packages/
    packages.json         which packages are turned on
    EmpirePackage.Water.dll   a turned-on package, compiled by the editor
  Audio/, Textures/ ...   any other folders you like

The project folder is the content root: every path in a scene, such as a mesh's Models/Crate.glb or a sound's Audio/Theme.mp3, is relative to it. Only Scenes/, Scripts/ and Packages/ have a fixed meaning; organise everything else however you like.

A folder without project.empire still opens

The Hub treats any folder with a scene in Scenes/ as a project. That is how a project made before the Hub existed, or created by hand, opens.

Empire Engine Hub

Run the Hub with dotnet run --project Hub, or start a packaged release: Empire Engine Hub.app on a Mac (drag it into Applications, then open it), or EmpireHub in the unzipped folder on Windows and Linux. It has three pages, and it can update itself (see Updating the Hub).

Projects

  • New project asks for a name, a location and an Empire Engine version, and makes a project folder with a starter scene: Scenes/Main.empirescene with a light, a camera, a ground and a cube, the starter models, an empty Scripts/ folder and project.empire.
  • Add existing… adds a project folder you already have.
  • Open starts the editor on the project's start scene. The … menu on each row has more actions.
  • The search box filters the list. Each row shows the project's editor version and when you last opened it.

A project name can't start or end with a space or contain / \ : * ? " < > |, and the folder it makes must be new or empty.

Installs

The editor versions the Hub knows about. A released Hub comes without an editor: the first thing to do is press Install version… and install one. Editors live in <hub>/Empire/<version>/ next to the Hub's files (on a Mac, where the Hub is an app that must be left as it came, in ~/Library/Application Support/EmpireHub/Empire/<version>/ instead). (Building the Hub from source also copies the editor you just built there.) Each row says where it came from: Built with the Hub, Downloaded from GitHub, or Located.

A project opens with the Empire Engine version it was made with. If that version isn't installed, the Hub asks which one to use (see Choosing the editor version). A project with no version recorded opens with the newest installed one.

  • Install version… downloads a version from GitHub (see below).
  • Locate… adds an editor folder from somewhere else, such as a build of your own (the folder holding empire.dll, or on a Mac the folder holding Empire Engine Editor.app, or the app itself). The Hub only remembers where it is.
  • Uninstall (on a version in the Hub's own folder) deletes that version after asking. Remove (on one you located) only forgets it and leaves its files alone. Projects are never touched; one made with an uninstalled version opens with the newest installed version until you install it again (the Hub will ask which version to use). An editor that is open can't be uninstalled, so close it first.

Choosing the editor version

Each project records the version it was made with in project.empire (editorVersion).

  • Changing it: on a project's row, open the … menu and choose Change editor version…. Pick one of the installed versions, or Any version to always use the newest. The Hub only edits project.empire; the project's files are not converted. A project saved by a newer version may not open in an older one, so back it up first if you're going back.
  • When the version isn't installed: pressing Open shows a window that says which version the project wants. It suggests the closest installed version (the lowest one that is at least as new, otherwise the newest), and you can pick another from the list. Press Open to use it for this time, or tick Also change this project to use that version to switch the project over so you're not asked again. Press Install … to download the version the project wants from GitHub; once it's installed the project opens with it. Cancel opens nothing.
  • If no editor is installed at all, the window only offers to install the version the project wants.

Installing other versions

Press Install version… next to Locate… on the Installs page. The Hub asks GitHub for the project's releases and lists them newest first: the current version (marked Latest), earlier ones, and pre-releases. Press Install on one and the Hub:

  1. downloads the release's zip for your computer (EmpireEngine-<version>-<platform>.zip), showing progress,
  2. checks it against the checksum GitHub lists for it,
  3. unpacks the editor into <hub>/Empire/<version>/ (the Application Support folder on a Mac, see above), next to any others:
0.1.0/    downloaded from the 0.1.0 release
0.1.1/    downloaded from the 0.1.1 release

The new version appears on the Installs page and in the version list when you make a new project, and projects made with it open with it. Cancel stops a download part-way and leaves nothing behind.

  • What's checked. Only github.com over https is trusted. A download that doesn't match its checksum, isn't a zip with an Empire Engine editor in it, or tries to write outside its folder (or contains a symbolic link) is refused and discarded. A version is moved into place only once it has unpacked completely.
  • Rows you can't install: a version that's already installed reads Installed, and a release with no zip for your computer says No download for <platform>.
  • Removing a version is the Uninstall button on its row. It only deletes a folder directly inside <hub>/Empire/ that holds an editor, never anything else.
  • If the list is empty or GitHub can't be reached, the window says why. Releases of a private repository can't be listed. GitHub also limits requests that aren't signed in to 60 an hour, which is plenty for this.
  • Write access. The Hub's own folder has to be writable. If you installed it somewhere protected (such as Program Files), move it to a folder you own.

About

The third-party software in the Hub and the editor, with each license. The editor shows the same list under Help > Credits. This page also has the update controls below and the Appearance choice: Light, Dark, or Match the system (the Hub follows your computer's light or dark setting and changes when it does). The Hub starts out dark; your choice applies at once and is remembered. Editors the Hub opens get the same look (see Light and dark). The opening screen with the logos stays dark in every theme, since the BRUTAL logo is made for a dark background.

Updating the Hub

When the Hub starts it asks GitHub once whether a newer Hub has been released. If there is one, a box appears at the bottom of the sidebar: press Update…. You can also press Check for updates… on the About page at any time, and untick Look for updates when the Hub starts there to stop the automatic check.

In the update window, Update and restart does this:

  1. downloads the new Hub's zip for your computer (EmpireEngineHub-<version>-<platform>.zip) and checks it against the checksum GitHub lists for it,
  2. unpacks it into a temporary folder and closes the Hub,
  3. lets the new Hub copy its files over the old Hub's folder, then starts the Hub again.
  • What is kept: your projects and settings (they live in the app data folder, not the Hub's folder), and every installed editor in <hub>/Empire/. An update never adds, replaces or removes an editor; use Install version… for that.
  • What is checked: only github.com over https is trusted, and an update with no checksum, a wrong checksum, or an unsafe path in its zip is refused. Nothing changes until the download is complete and checked.
  • When it can't update itself: a Hub run from a source build (dotnet run) or in a folder it can't write to says why, and the button opens the release page so you can download the new version yourself.
  • On a Mac the whole app is replaced, files only the old app had are removed, and the app is signed again (ad hoc, with the system's codesign) so macOS accepts it as one sealed app. If you opened the app straight from the Downloads folder, macOS runs it read-only and it can't change itself: drag it into Applications, open it from there, and update again. A Hub from before it was an app (a plain folder) can't update into the app, so download Empire Engine Hub.app once.
  • If it fails: the old Hub keeps running, and if the file swap itself fails the Hub starts again and shows what went wrong in the status line.

Which scene opens

The editor opens the project's StartScene from project.empire if it exists, otherwise Scenes/Main.empirescene, otherwise the first scene it finds.

Where the Hub keeps its settings

The project list, any installs you located by hand, and your choices (appearance, whether to look for updates) are saved in settings.json in the per-user app data folder: AppData on Windows, Application Support on macOS, and ~/.config on Linux.

For the exact contents of project.empire and the other files, see File formats.
