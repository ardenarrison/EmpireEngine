Game UI

Buttons, text fields, checkboxes, dropdowns and bars drawn over the game, in the editor's play mode and in built games alike. Drag a UI object onto a script's Button field and react to clicks with OnClick.

Adding UI

Right-click in the Hierarchy and pick one under UI: Button, Text Field, Checkbox, Dropdown or Bar. Each is its own object in the Hierarchy. You can also add a UI … component to any object.

Press UI in the toolbar to see the UI drawn over the scene, each element outlined with its kind and name; click one to select it. Press Done UI when finished.

The game's UI is drawn with the same renderer the editor uses for its own panels (Canvas2D), with its font built into the engine. The editor's play mode and a built game share the same code for drawing it and for handling clicks and typing, so a menu behaves the same in both.

Placement

X and Y are the element's top-left corner and W and H its size, all as fractions (0 to 1) of the game view. A button at X 0.4, Y 0.45, W 0.2, H 0.07 (the default) sits near the middle, a fifth of the view wide, and stays in place at any window size. Elements later in the Hierarchy are drawn on top and take clicks first.

Kinds

KindSettingsWhat the player does
ButtonLabel, Center TextClicks it: pressed and let go over it
Text FieldLabel (shown as a hint while empty), Default textClicks it, types, Backspace deletes, Enter submits, Escape or a click elsewhere lets go
CheckboxLabel, CheckedClicks anywhere on it to tick or untick
DropdownOptions (one comma-separated line, then Apply Options), Selected, Center TextClicks to open the list, clicks an option to pick it; a click elsewhere closes it
BarLabel, Value (0 to 1)Nothing: scripts set how full it is

Every kind also has Visible (off hides it, and hidden elements take no clicks) and, except bars, Interactable (off draws it dimmed and ignores the mouse and keyboard).

Using UI from scripts

Declare a public field of type Button, TextField, Checkbox, Dropdown or Bar. In the Inspector it is a slot: drag a UI object from the Hierarchy onto it. A slot only takes an object with a UI element of its kind, so a Button field won't accept a text field. When play starts, the field holds that object's control.

public class Menu : Behaviour
{
    public Button play;            // drag the Play button here
    public TextField playerName;
    public Checkbox sound;
    public Dropdown difficulty;
    public Bar health;

    public override void Start()
    {
        play.OnClick += StartGame;
        playerName.OnSubmit += name => play.Label = $"Play as {name}";
        sound.OnChanged += on => AudioListener.Volume = on ? 1f : 0f;
        difficulty.OnChanged += index => Console.WriteLine("Difficulty: " + difficulty.SelectedText);
    }

    public override void Update() => health.Value = SaveGame.GetFloat("health", 1f);

    private void StartGame() => SceneManager.LoadScene("Level1");
}

Add handlers in Start. They run on the frame the player clicks or types, before every script's Update. A handler that throws prints UI error in OnClick of 'Play' … and the other handlers still run. Lists and arrays work too: public List<Button> levelButtons;.

Finding a control from code

var quit = UiControl.From<Button>(Scene.FindObjectWithName("Quit"));   // null if missing or not a button
quit?.OnClick += () => Console.WriteLine("Bye");

UI and the rest of the game

MemberUse
GameUi.PointerOverUiTrue while the mouse is over a visible element or an open list. Skip game clicks then: if (Input.GetMouseButtonDown(0) && !GameUi.PointerOverUi) Shoot();
GameUi.IsTypingTrue while a text field has the keyboard, so movement keys can be ignored while the player types
Input.inputStringThe characters typed this frame, as in Unity

While the cursor is locked for mouse-look, the UI ignores the mouse. Unlock it (Input.cursorLocked = false) when you open a menu.

Escape in the editor

In the editor's play mode, Esc stops the game, so it can't be used to leave a text field there. Click elsewhere or press Enter instead. In a built game, Escape lets go of the field.
