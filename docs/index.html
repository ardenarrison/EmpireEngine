Empire Engine 0.2.6

Make 3D games in C#, from one editor.

Empire Engine is a 3D game engine written in C# on .NET 10. It draws with Vulkan, and its editor lets you place objects, write scripts in C# or snap them together from blocks, press Play to try the game, and build it into a program you can hand to other people.

What's in the engine

AreaWhat you get
RenderingA Vulkan renderer with physically based materials and textures, directional, point and spot lights, sun shadows, gradient or panorama skies, sky lighting, see-through surfaces and MSAA, FXAA and SMAA anti-aliasing.
ModelsglTF (.glb, .gltf), FBX and OBJ. Models reload in the editor as soon as you re-export them.
ScriptingC# scripts compiled with Roslyn. Public fields show up in the Inspector. Coroutines, collision callbacks and a Unity-style API.
Visual scriptingA block editor (events, motion, control, sensing, variables, operators) that writes a C# script for you.
PhysicsRigidbodies, box, sphere and mesh colliders, friction and bounce, forces in four modes, raycasts and collision events.
AudioMP3 and WAV playback with 2D and 3D sound, Doppler, rolloff, one-shots and a listener.
AnimationSkinned and node animation from glTF, played by id with cross-fades, and shared between characters that use the same bones.
TerrainHeightmap ground you sculpt with brushes, paint with up to eight color layers, or fill with generated hills. It is also a collider.
ParticlesA module-based particle system with shapes, bursts, color and size over life, ground collision and presets for fire, smoke and more.
Game UIButtons, text fields, checkboxes, dropdowns and bars drawn over the game, in the editor and in built games, with OnClick-style events for scripts.
Scenes and savesLoad scenes on their own or on top of each other, stream them in the background, and save the whole game into named slots.
TerminalA real terminal inside the editor (Window > Terminal), starting in your project's folder, with colors, full-screen programs, copy and paste.
AI assistantAn optional chat inside the editor that uses the Claude API with your own key. It is off until you agree to a notice, and sends nothing until you press Send.
PackagesOptional add-ons made of ordinary scripts. The editor comes with a Water package.
BuildingFile > Build Project makes a standalone game for Windows, macOS or Linux that needs nothing installed.

The parts

Empire Engine is a handful of programs and libraries that live together in this repository:

FolderWhat it is
Engine.Core/The engine itself, with no graphics: scenes, components, scripting runtime, physics, audio mixing, animation, asset loaders and the scene file format.
Engine.Brutal/The Vulkan renderer, window, keyboard and mouse, and audio output, built on the BRUTAL libraries. Also contains BrutalPlayer, which runs a scene in a window.
ScriptCompiler/Compiles a project's Scripts/ folder and its packages into DLLs with Roslyn.
Editor/The editor (the program is called empire). It uses an immediate-mode UI and includes the code view and the visual scripting view.
Player/The runtime that a built game is. It reads GameData/ and plays the start scene.
Hub/Empire Engine Hub, the launcher. It lists your projects, creates new ones and opens them in the right editor version.
Packages/Packages that ship with the editor (currently Water).
Tests/, Probe/The engine's test program, and a small tool that opens a scene in a game window without the editor.
publish.pyPackages the Hub, and the editor with the player, as separate zips to ship. The Hub comes without an editor and installs one from your GitHub releases.

See Engine architecture for how these fit together and what happens in one frame.

Open source

Empire Engine's code is open source under the Apache License 2.0: free to use, change and share, including in commercial games. Your games are yours. Two things aren't covered by that license: the Empire Engine name and crown logo (trademarks; forks need their own name), and the BRUTAL logo, which belongs to Ahwoo Limited and must stay on the splash screen every game opens with. Contributions are welcome; see CONTRIBUTING.md in the repository, and README.md for an overview.
