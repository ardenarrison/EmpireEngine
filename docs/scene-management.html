Scripting

Loading scenes and saving games

SceneManager moves between levels, layers scenes on top of each other and streams them in the background. SaveGame saves the whole game in named slots.

Loading a scene

SceneManager.LoadScene("Level2");                           // replace the current scene
SceneManager.LoadScene("Hud", LoadSceneMode.Additive);      // add to what's loaded
SceneManager.UnloadScene("Hud");                            // take a scene's objects out again
  • Names: a scene in the project's Scenes/ folder is named without its extension: "Level2", or "Wing/Hall" for Scenes/Wing/Hall.empirescene. A scene anywhere else is named by its path from the project folder: "Levels/Level2.empirescene".
  • Single (the default) replaces everything that's loaded, except objects marked with DontDestroyOnLoad. The new scene's settings and gravity take over.
  • Additive adds the scene's objects to the world.
  • Loading happens at the start of the next frame, before scripts run, so it's safe to call from anywhere, including in the middle of Update or a collision event.

One world

All loaded scenes share one world: their objects see each other, collide with each other and are lit by the same lights. Each object remembers which scene it came from (SceneObject.SceneName), which is how UnloadScene knows what to remove. Objects a script makes while playing belong to the active scene.

Streaming in the background

LoadSceneAsync reads the scene file, and loads its models and sounds, on another thread, then adds it at the start of a frame once it's ready. A big level can stream in as the player approaches without a stall.

public class HallTrigger : Behaviour
{
    private SceneLoadOperation? _loading;

    public override void OnCollisionEnter(SceneObject other)
    {
        if (other.Name == "Player" && _loading == null && !SceneManager.IsLoaded("Hall"))
            _loading = SceneManager.LoadSceneAsync("Hall", LoadSceneMode.Additive);
    }

    public override void Update()
    {
        if (_loading is { IsDone: true, Error: { } error })
            Console.WriteLine("Could not load the hall: " + error);
    }
}
SceneLoadOperationMeaning
IsDoneTrue once the scene is in the world (or loading failed)
Progress0 while reading, 0.9 when ready to add, 1 when added. For a loading bar.
ErrorWhy it failed, or null
Name, ModeWhat was asked for

Keeping objects between scenes

public override void Start() => SceneManager.DontDestroyOnLoad(Object);

The object and everything under it survive when a Single load replaces the scene. Good for music, a player that walks between levels, or a game manager. An object that has a parent is first moved to the top level, keeping its place in the world.

Saving the game

SaveGame.SetInt("coins", 12);     // your own values travel with the save
SaveGame.Save("slot1");           // every loaded scene, as it is right now, plus those values
SaveGame.Load("slot1");           // puts it all back at the start of the next frame

What a save keeps

  • Every object's transform and components, including a Rigidbody's velocity and an Audio Source's place in its clip
  • Every script's public fields
  • Which scenes are loaded, and which is active
  • Time.time
  • Every value set with SetInt, SetFloat, SetBool and SetString

Not kept: private fields, and anything else a script made up that isn't a public field. Put that in SetInt and friends, and read it back in OnGameLoaded.

After loading

Scripts that had already started when the game was saved don't run Start again. Their public fields are put back, then OnGameLoaded() is called, which is the place to rebuild cached references:

public class Enemy : Behaviour
{
    public float health = 100f;          // restored by the save
    private SceneObject? _player;        // not saved: find it again

    public override void Start() => FindPlayer();
    public override void OnGameLoaded() => FindPlayer();

    private void FindPlayer() => _player = Scene.FindObjectWithName("Player");
}

Your own values

MethodNotes
SetInt, SetFloat, SetBool, SetStringStore a value under a key
GetInt(key, default) and friendsRead it back, or the default when it isn't set
HasKey(key), DeleteKey(key)Check for or forget one value
ClearData()Forget every value. A new game starts with none.

These values live in memory and are written only when you call Save; loading a slot replaces them with the slot's.

Slots

MethodDoes
Save(slot)Writes the game to the slot, replacing what was there. Returns false (and prints why) if it couldn't.
Load(slot)Replaces the playing game at the start of the next frame. Returns false when the slot is missing or unreadable; the game carries on.
Exists(slot)Whether the slot has a save
Timestamp(slot)When it was saved, in local time, or null
Delete(slot)Removes it
Slots()The names of every slot with a save, sorted

Slot names are file names, so use letters, digits, spaces, dashes and underscores only.

Where saves go

  • Built game: <application data>/<game name>/Saves/
  • Playing in the editor: a folder for the project under your application data folder, so test saves don't end up in the project
  • You can point SaveGame.Directory somewhere else before saving

Each slot is one JSON file, <slot>.empiresave.
