Working with objects

Adding objects

Right-click in the Hierarchy for a menu of ready-made objects:

  • Objects: Add Object (empty), Add Camera
  • Lighting: Point Light, Spot Light, Directional Light, Environment (sky and ambient)
  • World: Terrain
  • Effects: Particle System, plus the particle presets Fire, Explosion, Embers and Smoke
  • Audio: Audio Source
  • UI: Button, Text Field, Checkbox, Dropdown, Bar

You can also drag a model from the Assets panel and drop it on the scene: it lands on the ground under the cursor (or 10 units ahead when there's no ground there). Dragging a sound onto the scene makes an object that plays it.

Selecting

  • Click a row to select just that object.
  • Shift-click selects every row from the last one you clicked.
  • Cmd-click (macOS) or Ctrl-click adds or removes one row.

The row you clicked last is the primary selection: the Inspector shows it and the handles sit on it. Moving or scaling changes every selected object by the same amount.

Parenting

Drag a row onto another row to make it a child. Add Child makes a new empty object under the selection, and the Inspector's Change Parent picks a parent from a list. Reparenting keeps an object where it is in the world; its position, rotation and scale are rewritten relative to the new parent.

Moving and scaling

Pick Move or Scale from the tool buttons and drag a handle. Move uses the world axes (arrow tips). Scale uses the object's own axes (box tips), and the center box scales evenly: drag right to grow and left to shrink. You can also type values in the Inspector's Position, Rotation and Scale fields, or drag across them.

Components

Press Add Component for the list of built-in components, followed by components from your own scripts and turned-on packages. Each component's section has an X on its title bar that removes it. See the Component reference.

Keyboard shortcuts

On macOS use Cmd; on Windows and Linux use Ctrl.

KeysAction

Cmd/Ctrl+DDuplicate the selected objects and their children (in the visual script view: duplicate the selected blocks)
EscIn order: stop play mode, cancel the exit prompt, stop typing in a field, close the open dialog, leave the visual script view. Otherwise it exits the editor (you're asked first if there are unsaved changes).

Undo covers changes to the scene made while editing. An edit becomes one undo step when it settles (no mouse button held, no field being typed in), so a whole drag is one step. Text fields keep their own undo while you type.

Play mode

Press Play to run the game inside the editor. The editor:

  1. saves a snapshot of the scene,
  2. builds any turned-on packages that changed, then compiles your Scripts/ folder (errors stop play and are shown),
  3. hides the panels and draws through the scene's first camera, exactly as the built game would,
  4. adds a camera and a sun if the scene has none, so there is always a view and a light.

Press Stop or Esc and the scene goes back to the snapshot. Changes made while playing are not kept. If a script locked the cursor for mouse-look, Esc also frees it.

Games played in the editor keep their save files in your application data folder, under the project's name, so they don't mix with the project.

The code view

Press Code to swap the 3D view for a C# editor over the project's Scripts/ folder. It colors C# as you type and compiles in the background a moment after each edit: problems are underlined, listed below the editor, and explained when the mouse rests on them. Scripts are checked against turned-on packages too, so using a package's classes is not an error.

  • Type a name in the header to make a new script.
  • Files changed outside the editor (in another IDE, say) are picked up within a second.
  • Generated scripts (the .cs files written from visual scripts) can be read and copied but not changed.
  • Press 3D view to go back. Esc stays inside the code view.

The visual script view

Press VC to build scripts from blocks. See Visual scripting.

UI mode

Press UI to see every game UI element outlined over the scene. Click one to select it and edit it in the Inspector. Press Done UI to go back. See Game UI.

Live reloading

Once a second the editor reloads models whose files changed on disk, so a re-export from Blender shows up right away. Scripts edited elsewhere are picked up the same way.

Light and dark

The editor has a light look and a dark one. Start it with --lightmode or --darkmode to choose; with neither, it uses your computer's setting (and is dark if the setting can't be read). The flag can go anywhere among the arguments:

empire --lightmode "My Game/Scenes/Main.empirescene" "My Game"

The Hub does this for you: it opens editors with the look you chose under About > Appearance (nothing is passed when that is Match the system, so the editor follows the system too). The look is chosen when the editor starts. It covers the panels, the code view, the visual script view, the terminal and the asset tiles; the 3D scene itself, and the logo screen every program opens with, are not themed.

Project settings

File > Project Settings… opens the settings that belong to this project. They are saved in project-settings.json in the project folder, so they travel with the project and with version control.

SettingWhat it does
Editor Far Clip Plane (10 to 100000, usually 500)How far from the editor's camera the scene is drawn, in world units. Anything farther away isn't drawn. Raise it to see distant objects, such as a big terrain's far edge, while you edit; lower it for finer depth detail close up.
Editor Near Clip Plane (0.01 to 100, usually 0.1)How close to the editor's camera things can be and still be drawn. Anything nearer isn't drawn. Lower it to look at small things up close without them being cut off; raise it for finer depth detail far away. It is never more than half the far plane, so lowering the far plane can pull the near plane in with it.

Drag a number, or click it to type one; Reset both to the usual values puts them back to 500 and 0.1. The editor's clip planes only change the camera you fly around the scene with. The cameras in your scene have their own Near and Far (set on the Camera component), which is what the game and Play mode use, so changing them doesn't change how the game looks. They apply at once and are saved when you let go of the mouse or close the window.
