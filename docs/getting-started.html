Getting started

Build Empire Engine from source, open the sample project, and make an object move with a script.

What you need

  • The .NET 10 SDK. Every project in the repository targets net10.0. Check with dotnet --version.
  • A GPU that supports Vulkan.
    • macOS: nothing to install. Apple Silicon is the tested platform; Intel Macs are experimental (the framework underneath ships no Intel Mac libraries, so the repository carries its own in ThirdParty/IntelMac/). The repository carries the Vulkan loader and MoltenVK in ThirdParty/Vulkan/osx-arm64/ and osx-x64/ (Apple Silicon and Intel), and the editor and built games bundle them.
    • Windows and Linux: an up-to-date graphics driver, which includes Vulkan.
  • Python 3, only if you want to package a release with publish.py.

Run Empire Engine Hub

The Hub is the easiest way in. Building it also builds the editor and places it where the Hub looks for installed editors.

dotnet run --project Hub

From the Hub, press New project, give it a name and a place, and open it. You can also add a project you already have. See Projects and Empire Engine Hub.

Or run the editor directly

The editor takes the scene to open, and optionally the project folder. When you leave the folder out, it is the folder above the scene's folder (so My Game/Scenes/Main.empirescene opens the My Game project).

# usage: empire <scene.empirescene> [contentRoot]
dotnet run --project Editor -- "/path/to/My Game/Scenes/Main.empirescene"
The starter project

A new project from the Hub has a scene with a sun, a sky, a camera and a flat green terrain for ground, plus empty Models/ and Scripts/ folders. Nothing is bundled: put your own .glb, .fbx or .obj models in Models/ and drag them onto the scene (see Models, textures and sound files).

Your first script

  1. Add something to move. Right-click in the Hierarchy panel on the left and choose Fire (under Effects). A flame appears in front of the editor camera, and needs no model files. (With a model of your own you could instead add an object with a Mesh component. The script below works on anything.)
  2. Make a script. Still in Add Component, pick Script. Type a name, for example Bob, and press Create and Attach. The editor writes Scripts/Bob.cs and attaches it.
  3. Write the code. Press Edit Code on the script in the Inspector (or the Code button in the toolbar) and replace the file with: 
    public class Bob : Behaviour
{
    public float height = 0.5f;   // shows in the Inspector as "Height"
    public float speed = 2f;

    private Vector3 _start;

    public override void Start()
    {
        _start = Object.Position;
    }

    public override void Update()
    {
        float y = MathF.Sin(Time.time * speed) * height;
        Object.Position = _start + new Vector3(0, y, 0);
    }
}
    Errors are underlined as you type and listed under the code. Save with Cmd+S (macOS) or Ctrl+S.
  4. Play. Press 3D view to go back to the scene, then Play at the top. The flame bobs up and down. Change Height in the Inspector and play again to see the difference.
  5. Stop. Press Stop or Esc. Everything goes back to how it was before you pressed Play.
No using lines needed

Every script is compiled with System, System.Collections.Generic, System.Linq, System.Numerics (for Vector3 and Quaternion), Engine.Core.Scene and Engine.Core.Scripting already imported. Adding them yourself does no harm.

Save and build

  • Save the scene with Cmd/Ctrl+S or File > Save Scene. Scenes are JSON files in Scenes/.
  • Build a game with File > Build Project…: pick a folder and a name, and the editor makes a standalone program. See Building and publishing.

Run the tests

The engine's tests are a console program that prints PASS or FAIL for each check and covers scenes and the file format, scripting, physics, audio, animation, terrain, particles, save games and more.

dotnet run --project Tests
