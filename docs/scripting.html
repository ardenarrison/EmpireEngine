Scripting

C# scripting

A script is a C# class in the project's Scripts/ folder. Attach it to an object and its Start and Update run while the game plays.

A first script

public class Mover : Behaviour
{
    public float speed = 5f;

    public override void Update()
    {
        float x = Input.GetAxis("Horizontal");   // -1 to 1 from A/D or the arrow keys
        float z = -Input.GetAxis("Vertical");    // W moves along -Z, which is "forward"
        Translate(x * speed * Time.deltaTime, 0, z * speed * Time.deltaTime);
    }
}

The rules:

  • The class name must match the file name: Mover lives in Scripts/Mover.cs.
  • It extends Behaviour. (A class that extends Component instead becomes a custom component.)
  • Don't put it in a namespace: the editor finds scripts by class name.
  • System, System.Collections.Generic, System.Linq, System.Numerics, Engine.Core.Scene and Engine.Core.Scripting are already imported.

Attaching a script

Select an object, press Add Component and choose Script. Pick an existing script, or type a new name and press Create and Attach, which writes a starter file:

// Runs every frame while the scene plays. The class name must match this file name.
public class Bob : Behaviour
{
    public override void Update()
    {
    }
}

The script's Inspector section has an Edit Code button that opens it in the code view. One object can carry any number of scripts, and one script can be on any number of objects; each gets its own instance.

What happens in one frame

  1. Time moves on (Time.deltaTime, Time.time).
  2. The keyboard and mouse are read (Input).
  3. Scenes and save games requested last frame are loaded.
  4. The game's UI takes its clicks and typing, and UI handlers such as OnClick run.
  5. Every script's Start (the first time) and Update run, in Hierarchy order.
  6. Spin components turn.
  7. Physics steps (at a fixed 60 steps per second, as many as the frame needs). Collision events fire here.
  8. Animators, particle systems and audio update.
  9. The frame is drawn.

There is no separate FixedUpdate. Forces added in Update are already scaled to the frame's length, so they push equally hard at any frame rate (see Forces).

When a script throws

An exception in any of these methods prints Script error in Mover on 'Player': … The script is stopped. to the console and stops that one script. The rest of the game keeps running.

The object and its transform

Object is the SceneObject the script is on. Read and set its Position, Rotation and Scale directly, or use the helpers:

Object.Position = new Vector3(0, 2, 0);
Object.Rotation = Quaternion.CreateFromYawPitchRoll(MathF.PI / 2, 0, 0);   // radians

Translate(0, 0, -1);   // move by x, y, z world units
Rotate(0, 90, 0);      // turn by x, y, z degrees
Scale(2, 2, 2);        // multiply the size (1, 1, 1 changes nothing)

string name = Object.Name;
SceneObject? parent = Object.Parent;

Position, rotation and scale are relative to the parent. For the world position of a child, use Object.WorldMatrix.Translation.

Which way is forward

Objects face along their local −Z. To get the world direction an object faces:

Vector3 forward = Vector3.Transform(-Vector3.UnitZ, Object.Rotation);
Vector3 right   = Vector3.Transform(Vector3.UnitX, Object.Rotation);

Position, rotation and scale

sceneObject is the object the script is attached to (the same one as Object), and its transform holds where it is:

sceneObject.transform.position = new Vector3(0, 2, 0);
sceneObject.transform.rotation = Quaternion.Identity;
sceneObject.transform.scale   *= 2f;

These are the object's own values, relative to its parent, and changing them moves the object at once.

Other components

var body = GetComponent<Rigidbody>();   // null when there is none
if (body != null) body.AddForce(0, 10, 0);

// Shortcuts that stop the script with a clear message when the component is missing:
rigidbody.AddForce(0, 10, 0, ForceMode.Impulse);
audioSource.Play();
animator.Play("Walk");

The capitalised forms Rigidbody, AudioSource and Animator work too. GetComponent<T>() finds the first component of that type on this object; to reach another object's components, use other.Components.OfType<T>().FirstOrDefault().

Inspector fields

A script's public fields appear in the Inspector, where you can change them per object. Values typed there are saved with the scene and copied into the script when play starts; fields you haven't touched keep the default your code gives them. Right-click a field to put it back to the script's default.

public class Turret : Behaviour
{
    public float range = 20f;                 // "Range"
    public int maxAmmo = 30;                  // "Max Ammo"
    public bool autoFire;                     // a checkbox
    public string label = "Turret";
    public Vector3 aimOffset;                 // three numbers
    public Vector3 beamColor = new(1, 0, 0);  // a color picker: the name ends in "Color"
    public Mode mode = Mode.Fast;             // a dropdown
    public SceneObject? target;               // drag an object from the Hierarchy onto it
    public List<SceneObject> waypoints = new();
    public float[] damageByLevel = { 5, 8, 12 };

    public enum Mode { [Label("Fast (inaccurate)")] Fast, Accurate }

    private float _cooldown;                  // private: not shown, not saved
}

float, double, int, longA number field

stringA text box
Vector3Three numbers, or a color picker when the field's name ends in Color
An enumA dropdown. [Label("…")] (or [Description("…")]) on a value changes the text shown; the value's name is what's saved.

Names are turned into labels the way Unity does it: jumpHeight becomes "Jump Height", _speed becomes "Speed". If you change a field's type so a saved value no longer fits, play still starts: the field keeps the script's default and a note is printed.

Coroutines

For things that happen over time (wait two seconds, then open the door) a script can run coroutines: methods that return IEnumerable<Wait> and yield to pause. Start one with Spawn, and call TickRoutines() once per frame from Update to keep them going.

public class Door : Behaviour
{
    public override void Start() => Spawn(OpenLater());

    public override void Update() => TickRoutines();

    private IEnumerable<Wait> OpenLater()
    {
        yield return WaitSeconds(2f);                          // pause for two seconds
        yield return GlideTo(Position + new Vector3(0, 3, 0), 1.5f);   // slide up over 1.5 s
        yield return WaitUntil(() => Input.GetKeyDown(Keys.E));        // until E is pressed
        yield return null;                                     // just one frame
        Object.Position -= new Vector3(0, 3, 0);
    }
}
YieldPauses until
yield return nullThe next frame
WaitSeconds(s)s seconds of game time have passed (affected by Time.timeScale)
WaitUntil(() => condition)The condition is true; checked once per frame
GlideTo(target, s)The object has slid in a straight line to target over s seconds

Any number of coroutines can run at once. Timer counts seconds since the script started (or since ResetTimer()). You can also make your own wait by extending Wait and overriding bool Update(float deltaTime) to return true when it's done. Visual scripts use exactly this machinery.

Collisions

public class Coin : Behaviour
{
    public override void OnCollisionEnter(SceneObject other)
    {
        if (other.Name != "Player") return;
        SaveGame.SetInt("coins", SaveGame.GetInt("coins") + 1);
        AudioSource.PlayClipAtPoint("Audio/Coin.wav", Object.Position);
        SceneManager.World!.Remove(Object);
    }
}

Collision events need colliders on both objects, and at least one of the two must have a Rigidbody. Use raycasts to find things without touching them.

Making and removing objects

Scripts can add objects to the scene that's playing and remove them again:

var ball = new SceneObject { Name = "Ball", Position = Object.Position + new Vector3(0, 1, 0) };
ball.Components.Add(new MeshRenderer { Model = "Models/Ball.glb" });
ball.Components.Add(new SphereCollider());
ball.Components.Add(new Rigidbody { Mass = 0.5f });
SceneManager.World!.Add(ball);              // or .Add(ball, parent)

SceneManager.World!.Remove(ball);           // takes it and its children out

The engine's own components work on objects made this way: the model is loaded the first time it's drawn, and physics picks up the new body on its next step. Script components are only started on objects that come from a scene, so to spawn something with behaviour, make it in its own scene and load that scene additively (SceneManager.LoadScene("Enemy", LoadSceneMode.Additive)).

How scripts are compiled

The editor compiles every .cs file in Scripts/ into one DLL with Roslyn each time you press Play, and Build Project compiles it into the game. The built game only loads that DLL; it never compiles anything.

  • Scripts are compiled with optimizations on, so they run at full speed.
  • unsafe code is allowed, and the engine's Vulkan bindings are referenced, so advanced scripts can talk to the GPU directly.
  • Scripts are compiled against the turned-on packages, so they can use the packages' classes. A script class wins over a package class with the same name.
