Using the editor

The terminal

A real terminal inside the editor, starting in your project's folder. Run git, dotnet, scripts, editors such as vim, or any command-line tool, without leaving the editor.

Opening it

Choose Window > Terminal, or press Ctrl+` (the key above Tab). A panel slides up along the bottom of the editor with your shell running in it: your own shell ($SHELL, for example zsh or bash) on macOS and Linux, and Windows PowerShell on Windows. Close the panel with the x or the same shortcut; the shell keeps running while it is hidden, with everything you were doing, and comes back when you reopen it. It stops when you close the editor.

Nothing runs until you open it, and it only runs what you type.

Typing in it

  • Click inside the panel to type. While the terminal has the keyboard, the editor's own shortcuts stand down and Esc goes to the program, not the editor. Click anywhere else in the editor to give the keyboard back. A solid cursor means it has the keyboard; a hollow one means it doesn't.
  • Arrow keys, Home, End, Page Up and Down, Delete, Tab (and Shift+Tab), the function keys, and Ctrl with a letter all work as in any terminal. Ctrl+C interrupts the running program and Ctrl+D ends input. The Interrupt button does the same as Ctrl+C.
  • Option or Alt with a key sends Escape first, which is how terminal programs read it.

The buttons along the top do the same: Copy, Paste, Interrupt (Ctrl+C), Clear (clears the screen and the history), and Restart (stops the shell and starts a new one). When the shell exits, the panel says so and Enter starts a new one. Pasting removes escape characters from the text first, so something copied from a web page can't smuggle in terminal controls, and programs that ask for it are told the text is a paste.

Full-screen programs

It is a full terminal emulator, not just a box of text: colors (16, 256 and true color), cursor movement, scrolling regions, the alternate screen, window resizing, and the questions programs ask a terminal. So editors, pagers, git log, top and tools with their own full-screen interfaces work. Box-drawing lines and block shapes are drawn as shapes. The editor's font only has plain English letters, though, so other characters show as a close ASCII character or ?: accented letters are shown without the accent, and symbols such as arrows and bullets as > and *.

The terminal tells programs its size, and follows the panel when the editor window changes size.

Using Claude Code (or another AI tool) here

If you have Claude Code installed, type claude in the terminal and use it as you would anywhere else; sign in when it asks, with your own Claude account or API key. That is Anthropic's own program running unmodified, so signing in works the way Anthropic intends, and Empire Engine never sees your login. The same goes for any other command-line tool. Empire Engine is not made, endorsed or supported by Anthropic. See also the AI assistant, which chats using your own API key.

Things to know

  • It runs as you. A command in the terminal can do whatever you can do on your computer, exactly like Terminal, PowerShell or any other terminal. Don't paste commands you don't understand.
  • Stopping. Closing the editor stops the shell and everything running in it. If the editor is killed or crashes, the shell notices within a couple of seconds and closes too.
  • One terminal, no tabs or split panes, and no mouse reporting to programs yet (a program can't see mouse clicks).
  • Windows uses the system's ConPTY (Windows 10 version 1809 or newer). That part has not been tested on a Windows computer yet.
  • macOS and Linux use the system's script command to make the terminal, so it needs to be installed (it is part of macOS and of util-linux on Linux).

For people changing the editor

  • The code is in Editor/Terminal/. TerminalEmulator (the screen), PtySession (the shell in a pseudo-terminal) and TerminalGlyphs (how characters are shown) are plain .NET and tested in Tests/; TerminalWindow is the panel.
  • The shell is started with script, inside a small watcher shell that closes it if the editor disappears. The terminal's size is changed later by running stty against its device.
  • While the terminal has the keyboard it sets Gui.ExternalTyping, which makes Gui.IsTyping true so the editor's shortcuts stand down.
