Custom components

A script class that extends Component instead of Behaviour becomes a new component, listed under its own name in Add Component. This is how packages such as Water add features.

Writing one

public class Bobber : Component
{
    public float Height = 0.5f;     // public fields show in the Inspector, as with scripts
    public float Speed = 2f;

    private Vector3 _start;

    public override void Start() => _start = Object.Position;

    public override void Update()
    {
        Object.Position = _start + new Vector3(0, MathF.Sin(Time.time * Speed) * Height, 0);
    }
}

Save it and it appears in Add Component as Bobber (script). Components from packages show the package's name instead, as in Water (Water package).

Behaviour or Component?

BehaviourComponent
Added withAdd Component > Script, then pick itAdd Component, under its own name
Start, UpdateYesYes
Inspector fieldsPublic fieldsPublic fields
Collision events, OnGameLoadedYesNo
Coroutines and helpers (Spawn, Translate, rigidbody…)YesNo
Found by other scripts with GetComponent<T>()NoYes

Pick Component for a reusable building block that other scripts look up by type (a Health component, a Water surface). Pick Behaviour for game logic that reacts to collisions or uses coroutines.

Finding a custom component

When play starts, the engine makes the component and puts it on the object right after its Script entry, so GetComponent finds it from any script on that object:

public class Health : Component
{
    public int Max = 100;
    public int Current;
    public override void Start() => Current = Max;
}

public class Hazard : Behaviour
{
    public int damage = 10;

    public override void OnCollisionEnter(SceneObject other)
    {
        var health = other.Components.OfType<Health>().FirstOrDefault();
        if (health != null) health.Current -= damage;
    }
}

Inside a component, Object is the object it's on and GetComponent<T>() finds its neighbours.

Drawing your own mesh

A component can replace what an object's Mesh draws by setting MeshRenderer.Mesh to a model built in code, and animate it by updating MeshRenderer.Pose every frame without building a new mesh. Neither is saved with the scene. The Water package does exactly this; its source in Packages/Water/Water.cs is a complete example, including working out the surface on background threads.

When it throws

As with scripts, an exception in Start or Update is printed and that component stops running. It stays on the object, so other scripts can still read its fields.

To share components between projects, put them in a package.
