Extending and shipping

Packages

A package is an optional add-on made of ordinary C# scripts. Install one in a project and its components appear in Add Component. Nothing in a package is part of the engine itself.

Installing a package

Open File > Package Manager…. It lists the packages that come with the editor, each with an Install button for this project, what it adds, whether it built, and how many components in the scene use it. No package is installed until you install it.

When you install one, the editor:

  1. adds its id to Packages/packages.json in the project,
  2. compiles its scripts into Packages/EmpirePackage.<Id>.dll,
  3. compiles your scripts again against it, so they can use its classes.

The DLL is rebuilt whenever the package's sources, its version or the engine changes; a .stamp file next to it records what it was built from. Play mode loads it, and Build Project copies it into the game.

Uninstalling deletes the DLL. Objects that use the package's components keep their settings and work again if you install it later. If an installed package is missing from the editor (say, a project opened with an older editor), the project keeps using the DLL it already has.

The Water package

Adds a Water component. Put it on an object whose Mesh is a flat plane (any plane model, such as one you exported from Blender) and, while the game plays, the plane becomes rolling, see-through water with crests, foam and sky reflections. Planes only, for now.

The sea is a sum of Gerstner waves, from long swells down to short chop, mostly travelling with the wind. Foam forms where crests pinch together, and a scrolling ripple texture adds detail finer than the grid. Wave sizes are in world units, so scaling the object makes more water, not bigger waves.

The surface is worked out on background threads across all CPU cores while the previous frame is drawn, so it adds little to the frame time.

Writing a package

Packages live in the repository's Packages/ folder, one subfolder each. The editor's build copies that folder next to the editor, and the Package Manager lists every subfolder that has a package.json.

{
  "id": "Floaty",
  "name": "Floaty",
  "version": "1.0.0",
  "description": "Adds a Floaty component that makes objects bob on the spot."
}
public class Floaty : Component
{
    public float Height = 0.3f;
    public float Speed = 1.5f;
    private Vector3 _start;

    public override void Start() => _start = Object.Position;

    public override void Update() =>
        Object.Position = _start + new Vector3(0, MathF.Sin(Time.time * Speed) * Height, 0);
}
  • The id must be letters, digits and underscores; it names the DLL. Without one, the folder's name is used. version defaults to 1.0.0.
  • Write the scripts exactly like a project's own. Classes that extend Component become new components; the usual imports are already there.
  • Bump version when you change a package, so projects rebuild it.
  • A project script with the same class name as a package class wins.

Use Packages/Water/Water.cs as a worked example of a substantial package.
